Come funziona How it works

Pipeline di Import Import Pipeline

Dal drag&drop di un PDF a una voce bibliografica completa, arricchita da API accademiche e AI locale, deduplicata, indicizzata e integrata nel Knowledge Graph. From drag&dropping a PDF to a complete bibliographic entry, enriched by academic APIs and local AI, deduplicated, indexed and integrated into the Knowledge Graph.

La pipeline di CiteMind è modulare e resiliente: se un'API non risponde o un campo non viene trovato, il sistema passa automaticamente alla fonte successiva. L'AI locale (Ollama) entra in gioco solo come ultimo fallback, garantendo sempre il massimo livello di completezza possibile senza dipendere da servizi cloud. CiteMind's pipeline is modular and resilient: if an API doesn't respond or a field isn't found, the system automatically falls back to the next source. Local AI (Ollama) kicks in only as a last resort, always guaranteeing the highest possible completeness without relying on cloud services.

Flusso completo Full flow

8 Step dalla sorgente al database The 8 stages

1

Drop — Acquisizione sorgente Drop

L'utente fornisce la sorgente tramite drag&drop nell'interfaccia o input diretto. CiteMind accetta PDF trascinati nella finestra principale, file BibTeX (.bib), RIS, CSV batch, DOI incollato nel campo di ricerca rapida e URL di pagine web. The user drags and drops a PDF, .bib, .ris, .csv file, or pastes a DOI / URL directly into the application. The type is detected automatically.

PDF BibTeX .bib RIS CSV DOI diretto URL
2

PDF Parse — Estrazione metadati locali PDF Parse

Per i file PDF, CiteMind usa PyMuPDF (fitz) per estrarre il testo grezzo delle prime pagine. Vengono identificati con euristiche il titolo (prima riga di grande dimensione), gli autori (seconda/terza riga), l'anno di pubblicazione e il journal tramite pattern matching sul layout tipografico del documento. PyMuPDF extracts text from the PDF. Title, authors, year and DOI are identified using heuristics on the first pages. A confidence score is assigned to each field.

PyMuPDF Title detection Author heuristics OCR fallback
3

DOI Extraction — Rilevamento identificatore DOI Extraction

Il sistema applica espressioni regolari sul testo estratto per rilevare DOI nel formato standard (10.XXXX/...). Il DOI viene ricercato nel corpo del testo, nelle note a piè di pagina e nei metadati XMP del PDF. Un DOI trovato permette un arricchimento API molto più preciso degli stessi metadati estratti in locale. A regex scans the full text for DOI patterns (10.XXXX/...). The extracted DOI is used to query academic APIs with higher precision.

Regex DOI XMP metadata Footnote scanning
4

API Enrichment — Arricchimento da fonti accademiche API Enrichment

CiteMind interroga in cascata tre API accademiche per arricchire i metadati. Per ogni campo (titolo, autori, anno, journal, abstract, ISBN, publisher) viene calcolato un confidence score. In caso di conflitto tra fonti, vince il campo con confidence più alta. Le API vengono interrogate nell'ordine: Crossref, OpenAlex and Semantic Scholar are queried in order. Each source returns a confidence score per field; conflicts are resolved by taking the highest-confidence value. Data includes abstract, keywords, volume, issue and pages.

Crossref OpenAlex Semantic Scholar

1. Crossref — DOI resolver principale, dati editoriali precisi
2. OpenAlex — metadati open access, affiliazioni, topics
3. Semantic Scholar — abstract arricchito, citazioni, field of study

5

AI Fallback — Inferenza locale con Ollama AI Fallback

Se dopo l'enrichment da API rimangono campi critici vuoti (es. titolo, autori, anno), CiteMind usa Ollama in locale con il modello gemma4 per inferire i metadati mancanti dal testo grezzo del PDF. L'AI genera anche note di sintesi e topic tematici associati al documento. Nessun dato lascia il computer dell'utente. If metadata fields are still missing after the API phase, the local Ollama model (recommended: gemma4) infers them from the PDF text. Processing is fully local — no data leaves your machine.

Ollama gemma4 Note generation AI Topics Locale / Privacy
6

Dedup Check — Controllo duplicati Dedup Check

Prima di inserire la nuova voce, CiteMind verifica che non esista già nel database un documento identico. Il controllo avviene in due modi: DOI exact match (se disponibile) e title fuzzy match usando distanza di Levenshtein normalizzata. Se viene rilevato un possibile duplicato, l'utente viene avvisato con un dialog di conferma. Before insertion, a duplicate check is performed by DOI and title similarity. If a match is found, the existing entry is updated rather than creating a duplicate.

DOI exact match Fuzzy title Levenshtein
7

Insert + Embed — Salvataggio e indicizzazione Insert + Embed

La voce viene inserita nel database SQLite con tutti i metadati arricchiti. Vengono aggiornati automaticamente i trigger FTS5 per la full-text search su titolo, autori, journal e note. In parallelo viene calcolato il vettore embedding del documento (concatenazione di titolo + abstract + keywords) per la ricerca semantica futura. The entry is saved to SQLite. FTS5 triggers index title, authors, journal and notes for full-text search. Embedding vectors are generated for semantic search (cosine similarity).

SQLite FTS5 triggers Embeddings Cosine similarity
8

Graph Update — Aggiornamento Knowledge Graph Graph Update

Dopo l'insert, il Knowledge Graph viene ricalcolato per includere il nuovo documento. Vengono estratte le keyword TF-IDF, creati i nodi documento e keyword, e calcolati gli archi di relazione tramite Jaccard overlap (soglia 0.35) e similarità semantica tra embedding. Vengono anche indicizzati gli archi DAG basati sulle citazioni (@references) se presenti nei metadati. The Knowledge Graph is updated with new document and keyword nodes. Edges are computed via Jaccard keyword overlap (threshold 0.35) and semantic similarity from embeddings. The force-layout is recomputed.

TF-IDF keywords Jaccard ≥ 0.35 Semantic edges DAG references Force layout
Visualizzazione Visualisation

Knowledge Graph The Knowledge Graph

Il Knowledge Graph trasforma la tua biblioteca in una mappa visiva delle relazioni concettuali tra documenti e argomenti. The Knowledge Graph transforms your library into a visual map of conceptual relationships between documents and topics.

🔵

Nodi Documento Document Nodes

Ogni documento importato diventa un nodo nel grafo. La dimensione del nodo riflette il numero di connessioni (grado). Cliccando su un nodo si accede al dettaglio della voce bibliografica. Each imported document becomes a node in the graph. The size of the node reflects the number of connections (degree). Clicking on a node gives access to the details of the bibliographic entry.

🟣

Nodi Keyword Keyword Nodes

Le keyword estratte via TF-IDF diventano nodi di tipo secondario. Un documento è collegato alle sue keyword con archi di peso proporzionale alla rilevanza TF-IDF nel corpus. Keywords extracted via TF-IDF become secondary nodes. A document is linked to its keywords with edges of weight proportional to the TF-IDF relevance in the corpus.

🔗

Archi di Relazione Relationship Edges

Gli archi tra documenti sono calcolati con Jaccard overlap sulle keyword condivise (soglia 0.35) e similarità coseno tra i vettori embedding. Gli archi DAG rappresentano citazioni esplicite. Edges between documents are calculated with Jaccard overlap on shared keywords (threshold 0.35) and cosine similarity between embedding vectors. DAG edges represent explicit citations.

Il grafo usa un force-directed layout: i documenti più simili si attraggono, formando cluster tematici naturali. Puoi zoomare, trascinare i nodi e filtrare per tipo di relazione. Apri il Knowledge Graph dal menu principale o con Ctrl+G. The graph uses a force-directed layout: similar documents attract each other, forming natural thematic clusters. You can zoom, drag nodes and filter by relationship type. Open the Knowledge Graph from the main menu or with Ctrl+G.
