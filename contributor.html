Contribuisci a CiteMind Contribute to CiteMind

CiteMind è un progetto open source che vive grazie alla community. Ogni contributo, grande o piccolo, è prezioso e benvenuto. CiteMind is an open-source project that welcomes contributions of all kinds. Whether you find a bug, have an idea, or want to write code — every contribution counts.

CiteMind nasce come progetto personale ed è rilasciato sotto licenza MIT. Chiunque può contribuire: non serve essere esperti di Python o di biblioteche accademiche. Segnalare un bug, suggerire una feature o migliorare la documentazione sono già contributi di grande valore. CiteMind started as a personal project and is released under the MIT licence. Anyone can contribute: you don't need to be an expert in Python or academic libraries. Reporting a bug, suggesting a feature, or improving the documentation are already highly valuable contributions.

Modi per contribuire Ways to contribute

Come puoi aiutare How to contribute

🐛

Bug Reports Bug Reports

Hai trovato un comportamento inaspettato? Apri una Issue su GitHub descrivendo il problema, i passaggi per riprodurlo e il tuo sistema operativo. Screenshot e log sono molto utili. Found a bug? Open an issue on GitHub with steps to reproduce it, the expected vs actual behaviour, and your OS version. Screenshots and logs are very useful.

→ Segnala un bug → Report a bug
✨

Feature Requests Feature Requests

Hai un'idea per migliorare CiteMind? Apri una Discussion su GitHub nella sezione "Ideas". Descivi il caso d'uso, il problema che risolverebbe e come immagini l'implementazione. Have an idea for a new feature? Open a GitHub Discussion to share it with the community. Describe the use case, the problem it solves, and how you envision the implementation.

→ Proponi una feature → Propose a feature
🔧

Pull Requests Pull Requests

Vuoi implementare qualcosa direttamente? Fai un fork del repository, crea un branch descrittivo, implementa le modifiche e apri una Pull Request verso main. Fork the repository, create a descriptive branch, make your changes and open a Pull Request with a clear description towards main.

→ Fork il repo → Fork the repo
📖

Documentazione Documentation

La documentazione può sempre essere migliorata. Correzioni di typo, aggiunta di esempi, traduzioni e guide più chiare sono contributi preziosi che aiutano tutti gli utenti. Help improve documentation, fix typos or translate content. Even small improvements make a big difference.

🌍

Traduzioni (i18n) Translations

CiteMind supporta la localizzazione tramite file di lingua. Se conosci una lingua non ancora supportata, puoi aggiungere un file di traduzione seguendo il pattern dei file esistenti in locales/. CiteMind already supports i18n. Add or improve a translation by editing the language files in the repo.

⭐

Supporto e condivisione Star & Share

Non sei sviluppatore ma vuoi supportare il progetto? Condividilo con i colleghi e lascia una stellina su GitHub, aiuta moltissimo! The simplest way to support CiteMind: star it on GitHub and share it with colleagues who do academic research.

Guidelines

Convenzioni e linee guida Conventions and guidelines

Per mantenere il codice coerente e le revisioni efficienti, seguiamo alcune convenzioni di base. To keep the code consistent and reviews efficient, we follow some basic conventions.

🐍

Stile Python Python Style

Il codice segue PEP 8. Usa nomi descrittivi, commenta le funzioni pubbliche con docstring, evita righe oltre 100 caratteri. Formatta con black prima di fare commit. The code follows PEP 8. Use descriptive names, comment public functions with docstrings, avoid lines over 100 characters. Format with black before committing.

🌿

Branch naming Branch naming

Usa nomi di branch descrittivi: feature/nome-funzione, fix/descrizione-bug, docs/sezione-aggiornata. Non fare commit direttamente su main. Use descriptive branch names: feature/feature-name, fix/bug-description, docs/updated-section. Do not commit directly to main.

💬

Commit messages Commit messages

Segui il formato Conventional Commits: feat: aggiunge import RIS batch, fix: corregge parsing DOI con trattino, docs: aggiorna README sezione AI. Follow the Conventional Commits format: feat: adds batch RIS import, fix: fixes DOI parsing with dash, docs: updates AI section in README.

🧪

Test Tests

Per funzionalità core (pipeline, export, FTS), aggiungi test nel folder tests/ usando pytest. Assicurati che tutti i test esistenti passino prima di aprire la PR. For core features (pipeline, export, FTS), add tests in the tests/ folder using pytest. Ensure all existing tests pass before opening the PR.

Processo PR: Apri la PR con una descrizione chiara di cosa fa e perché. Collega l'Issue correlata con Closes #numero. Il maintainer revisionerà entro qualche giorno. Non scoraggiarti se vengono richieste modifiche: è normale e costruttivo. PR Process: Open the PR with a clear description of what it does and why. Link the related Issue with Closes #number. The maintainer will review within a few days. Do not get discouraged if changes are requested: it is normal and constructive.
